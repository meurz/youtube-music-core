Version 0.7.0 completes the desktop core APIs while keeping every account, catalog and playback request on the official Music Web client (`WEB_REMIX`).

- Native operation handles support cancellation during HTTP I/O, player execution and lock waits, whole-operation deadlines, and phase progress. The .NET wrapper connects cancellation and progress to these native operations. Legacy C entry points remain compatible; capability discovery reports protocol 1.1 / ABI 2.
- Playback adds real player prewarming, bounded next-track prefetch, an eight-entry stream cache, URL refresh and explicit reset. Player source expires after six hours; cached URLs expire after five minutes or when their remaining validity reaches 90 seconds. Qualifying stream failures get one fresh bootstrap, with generation checks preventing stale cache repopulation.
- Structured errors distinguish cancellation, timeout and rate limiting. Reads retry transient failures at most three attempts and honor bounded Retry-After delays. Writes are never automatically replayed; uncertain outcomes return `mutation_outcome_unknown` with `retryable:false` and require reconciliation before retrying.
- Library edits support song and playlist ratings, server-provided save/remove tokens, artist subscriptions, and playlist creation, metadata/privacy changes, deletion, append, removal and reordering. Returned action metadata and unique playlist entry IDs support duplicate-safe edits.
- Discovery adds search suggestions, home/explore feeds with filter context and pagination, richer queue context, lyrics timing availability and account enumeration. Verified account selection creates an independent client without exposing credentials.
- The release matrix adds Windows ARM64 alongside Windows x64, Linux x64/ARM64 and macOS Intel/Apple Silicon. Archive availability and native build validation are determined by the release workflow.

Offline validation covers cancellation/deadlines, bounded reads versus unreplayed writes, stream-cache lifetime/generations, mutation contracts, discovery pagination, lyric timing validation and identity selection. Live Web reads passed search suggestions, filtered and paginated home feeds, explore, automix queues and continuation, plain lyric fallback, account cloning and mismatched-identity rejection. Release checks separately validate the platform artifacts and native/.NET integration.

Cookie maintenance and verified encrypted CLI persistence remain available. Revoked sessions still need browser reimport. Lyrics receive timestamps only when the Web response supplies them; the tested Web track returned plain lyrics. Account enumeration only covers identities exposed by the imported Music session, and some identities may require separate import. Cold player preparation still takes tens of seconds; schedule prewarm off the UI thread.

Audio decoding, full-track playback, seek/buffering, playback policy, SMTC and UI belong to the host. CDN probes do not replace actual MediaPlayer acceptance tests. PO-token generation, SABR and DRM are unsupported. Cancellation or network failure during a write can leave an uncertain server outcome; reload before retrying.

Archives contain the CLI, native library, C header, documentation, .NET example and third-party licenses. Verify SHA256SUMS before installing. Linux requires compatible glibc (2.39 or newer); Windows/macOS binaries are unsigned.
